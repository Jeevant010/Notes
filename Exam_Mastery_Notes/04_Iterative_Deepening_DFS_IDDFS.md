## 🧭 Executive Summary: What This Module Is About

In AI search, we face a classic dilemma:
- **Breadth-First Search (BFS)** is complete and finds the shallowest solution, but its **memory footprint $O(b^d)$ explodes exponentially**, crashing computers within minutes on large search spaces.
- **Depth-First Search (DFS)** uses virtually no memory ($O(bd)$), but it can **plunge down infinite paths**, loop endlessly, and miss a shallow, perfect solution right under its nose.

**Iterative Deepening Depth-First Search (IDDFS)** solves this dilemma. It runs Depth-Limited Search (DLS) repeatedly with gradually increasing depth limits ($L = 0, 1, 2, 3, \dots$). It gives you **the completeness and shallowest-depth optimality of BFS** with **the tiny, linear memory footprint of DFS**!

---

## 1. The Search Dilemma: Why BFS & DFS Fall Short

```
                            BFS                                           DFS
              [ A ]                                         [ A ]
             /     \                                       /     \
          [ B ]   [ C ]                                 [ B ]   [ C ]
          /   \   /   \                                 /
       [ D ] [E] [F]  [G]                            [ D ]
                                                     /
    Explores level by level                       [ H ]  (Can wander infinitely deep!)
    • Memory: O(b^d) -> EXPONENTIAL EXPLOSION!    • Memory: O(b * m) -> Linear, efficient!
    • Complete? YES                               • Complete? NO (loops in infinite trees)
    • Optimal? YES (unweighted)                   • Optimal? NO (returns first deep path)
```

### Depth-Limited Search (DLS)
To prevent DFS from wandering infinitely, we can impose a cutoff depth $L$:
- Discards any paths that go deeper than limit $L$.
- **The Catch**: If we don't know the depth $d$ of the goal:
  - If we pick $L < d$: DLS fails to find the goal (returns failure).
  - If we pick $L > d$: DLS wastes time exploring unnecessarily deep paths and can return a suboptimal path.

---

## 2. The IDDFS Strategy: "Repeated DFS with Increasing Limits"

IDDFS systematically overcomes the mystery of unknown goal depth:
1. Start with depth limit **$L = 0$**. Run DFS from the root up to depth 0.
2. If goal is not found, increment depth limit to **$L = 1$**. Run DFS from the root up to depth 1.
3. If goal is not found, increment depth limit to **$L = 2$**. Run DFS from the root up to depth 2.
4. Continue incrementing $L = 0, 1, 2, 3, \dots, d$ until the goal is found or the maximum search space is exhausted.

```
   Iteration L=0:   Root only
   Iteration L=1:   Root + Level 1
   Iteration L=2:   Root + Level 1 + Level 2
   ...
   Iteration L=d:   Root + Level 1 + ... + Level d  ===> GOAL FOUND!
```

## 3. The Mathematical Proof: Why Node Re-expansion Is Cheap!

The most common objection students make in exams is:  
> *"Doesn't IDDFS waste a massive amount of time re-generating nodes from the root on every single iteration?"*

The answer is **NO**. In any exponential search tree, **the bottom layer contains vastly more nodes than all previous layers combined**.

### Mathematical Derivation of Total Node Expansions
Let $b$ be the branching factor, and $d$ be the depth of the shallowest goal.

In IDDFS:
- The root node (depth 0) is generated **$d + 1$** times.
- Nodes at depth 1 are generated **$d$** times.
- Nodes at depth 2 are generated **$d - 1$** times.
- ...
- Nodes at the goal depth $d$ are generated **$1$** time.

Total nodes generated by IDDFS:
$$N(\text{IDDFS}) = (d+1)b^0 + d \cdot b^1 + (d-1)b^2 + \dots + 2 \cdot b^{d-1} + 1 \cdot b^d$$

In comparison, in Breadth-First Search (BFS), every node up to depth $d$ is generated once:
$$N(\text{BFS}) = 1 \cdot b^0 + 1 \cdot b^1 + 1 \cdot b^2 + \dots + 1 \cdot b^d$$

---

### 🔢 Concrete Numerical Example: Branching Factor $b = 10$, Depth $d = 5$

Let's plug in real numbers:
- **BFS Expansions**:
  $$N(\text{BFS}) = 1 + 10 + 100 + 1,000 + 10,000 + 100,000 = \mathbf{111,111\ \text{nodes}}$$

- **IDDFS Expansions**:
  $$N(\text{IDDFS}) = 6(1) + 5(10) + 4(100) + 3(1,000) + 2(10,000) + 1(100,000)$$
  $$N(\text{IDDFS}) = 6 + 50 + 400 + 3,000 + 20,000 + 100,000 = \mathbf{123,456\ \text{nodes}}$$

### The Ratio:
$$\frac{N(\text{IDDFS})}{N(\text{BFS})} = \frac{123,456}{111,111} \approx \mathbf{1.11}$$

> **Conclusion for Exam**:  
> IDDFS incurs **only about 11% computational overhead** compared to BFS! In return for that tiny 11% extra time, IDDFS reduces the memory requirement from **$100,000$ nodes in memory (several gigabytes)** down to just **$b \cdot d = 10 \times 5 = 50$ nodes in memory (a few kilobytes)**!  
> Asymptotically, both have the same time complexity: $\mathbf{O(b^d)}$.

## 4. Step-by-Step Worked Graph Example

### The Graph (From Course Presentation)
Consider the following directed graph where Start = $A$ and Goal = $G$:

```
               [ A ]  (Depth 0)
              /     \
           [ B ]   [ C ]  (Depth 1)
           /           \
        [ D ]         [ E ]  (Depth 2)
        /
     [ G ]  (Goal at Depth 3)
```

### Trace of IDDFS Iterations

#### 📍 Iteration 0 (Depth Limit $L = 0$):
- Visit: `A`
- Goal test on `A`: False.
- Cutoff reached.
- Result: Goal not found. Increment limit.

#### 📍 Iteration 1 (Depth Limit $L = 1$):
- Visit: `A`
  - Descend to `B` (depth 1) $\to$ Goal test on `B`: False. Cutoff reached.
  - Backtrack to `A`.
  - Descend to `C` (depth 1) $\to$ Goal test on `C`: False. Cutoff reached.
- Nodes visited this iteration: `A, B, C`.
- Result: Goal not found. Increment limit.

#### 📍 Iteration 2 (Depth Limit $L = 2$):
- Visit: `A`
  - Descend to `B` (depth 1)
    - Descend to `D` (depth 2) $\to$ Goal test on `D`: False. Cutoff reached.
  - Backtrack to `A`.
  - Descend to `C` (depth 1)
    - Descend to `E` (depth 2) $\to$ Goal test on `E`: False. Cutoff reached.
- Nodes visited this iteration: `A, B, D, C, E`.
- Result: Goal not found. Increment limit.

#### 📍 Iteration 3 (Depth Limit $L = 3$):
- Visit: `A`
  - Descend to `B` (depth 1)
    - Descend to `D` (depth 2)
      - Descend to `G` (depth 3) $\to$ **Goal test on `G`: TRUE!**
- Nodes visited this iteration: `A, B, D, G`.
- **Returned Path**: $\mathbf{A \longrightarrow B \longrightarrow D \longrightarrow G}$
- **Solution Depth**: $d = 3$. **SEARCH TERMINATES SUCCESSFULLY!**

## 5. Handling Cycles and Repeated States in Graphs

In a search tree, no loops exist. But in real-world graphs, undirected or cyclic edges can cause naive DFS to loop indefinitely within a single depth limit (e.g., $A \to B \to A \to B \dots$).

### Solutions:
1. **Path-Based Visited List (Call-Stack Check)**:
   - Within the recursive DFS call stack, check if a child node is already an ancestor on the current path from the root.
   - If yes, prune the child immediately.
   - *Memory cost*: Zero additional memory beyond the current path ($O(d)$).
2. **Graph-Search IDDFS (Global Explored Table)**:
   - Maintains an explored table recording the minimum depth at which each node was visited.
   - If a node is encountered at a depth greater than or equal to its recorded depth, prune it.
   - *Trade-off*: Reduces re-visited nodes, but increases memory usage.

## 6. Comprehensive Head-to-Head Comparison: BFS vs. DFS vs. IDDFS

*(Direct question frequently asked for 6–8 marks)*

| Feature | Breadth-First Search (BFS) | Depth-First Search (DFS) | Iterative Deepening DFS (IDDFS) |
| :--- | :--- | :--- | :--- |
| **Exploration Strategy** | Level by level (shallowest first) | Follows single branch deeply | Repeated DFS with increasing depth limits |
| **Frontier Data Structure** | FIFO Queue | LIFO Stack (or recursion) | Call Stack (Recursion with depth counter) |
| **Time Complexity** | $O(b^d)$ | $O(b^m)$ ($m$ = max depth) | $O(b^d)$ |
| **Space Complexity** | $\mathbf{O(b^d)}$ *(Exponential - Awful!)* | $\mathbf{O(b \cdot m)}$ *(Linear - Great!)* | $\mathbf{O(b \cdot d)}$ *(Linear - Optimal!)* |
| **Completeness** | **Yes** (if $b$ is finite) | **No** (fails on infinite depth) | **Yes** (if $b$ is finite) |
| **Optimality** | **Yes** (for unit step costs) | **No** (suboptimal) | **Yes** (for unit step costs / shallowest depth) |
| **Best Used When** | Shallow goal, abundant RAM | Very large tree, memory strictly limited | **General uninformed search when solution depth is unknown and RAM is limited** |

## 7. Real-World Applications of IDDFS
1. **Two-Player Board Games (Chess, Checkers)**:
   - In time-limited competitive game playing, an AI engine doesn't know how deep it can search before the clock runs out.
   - IDDFS searches to depth 1, then depth 2, then depth 3... If time runs out at depth 5, the engine simply plays the best move found at depth 4! (This is called **Anytime Algorithm** behavior).
2. **Puzzle Solvers (8-Puzzle, 15-Puzzle, Rubik's Cube)**:
   - Finding the shortest sequence of moves with minimal memory overhead.
3. **Robotic Motion Planning**:
   - Safely exploring short action plans without allocating massive memory buffers.
