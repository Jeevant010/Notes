## 🧭 Executive Summary: What This Module Is About

In this module, we examine the two most powerful informed search algorithms in Artificial Intelligence:
1. **A\* Search Algorithm**: The undisputed gold standard for finding the shortest path in state spaces. It combines the accumulated path cost $g(n)$ with the future heuristic estimate $h(n)$ through the formula $f(n) = g(n) + h(n)$. When $h(n)$ is **admissible**, A* is mathematically guaranteed to find the optimal path.
2. **AO\* Search Algorithm**: Extends heuristic search to **AND-OR Graphs** (problem-reduction representations). When solving a problem requires decomposing it into multiple mandatory sub-problems (AND branches) alongside alternative choices (OR branches), AO* finds an optimal **solution tree** using **bottom-up cost propagation**.

# PART 1: The A* Search Algorithm

---

## 1. The Core Philosophy and Formula

A* balances past experience with future potential:
$$\mathbf{f(n) = g(n) + h(n)}$$

Where:
- **$g(n)$**: The **exact actual cost** incurred so far to travel from the Start node to node $n$.
- **$h(n)$**: The **estimated cost** to travel from node $n$ to the nearest Goal state (the heuristic).
- **$f(n)$**: The **estimated total cost** of the cheapest complete solution path passing through node $n$ from start to goal.

```
       [ Start S ] ═════════════════════> [ Node n ] ╍╍╍╍╍╍╍╍╍╍╍╍╍╍╍> [ Goal G ]
       |                                           |                           |
       +────────────────── g(n) ───────────────────+───────────── h(n) ───────+
       |                                                                       |
       +───────────────────────────────── f(n) ────────────────────────────────+
```

### Why A* Outperforms UCS and Greedy BFS
- If $h(n) = 0$ everywhere $\implies f(n) = g(n) \implies$ A* becomes **Uniform Cost Search (UCS)** (guaranteed optimal, but explores blindly in circles).
- If $g(n) = 0$ everywhere $\implies f(n) = h(n) \implies$ A* becomes **Greedy Best-First Search** (fast, but makes stupid mistakes and is suboptimal).
- A* uses $g(n)$ to keep the search honest and optimal, while using $h(n)$ to pull the search laser-focused toward the goal!

---

## 2. Conditions for Optimality: Admissibility & Consistency

Examiners ask about these two conditions in almost every exam. Memorize them word-for-word!

### 1. Admissibility (Heuristic Never Overestimates)
> *"A heuristic function $h(n)$ is **admissible** if it never overestimates the true cost to reach the nearest goal state."*

$$\mathbf{0 \le h(n) \le h^*(n) \quad \forall n}$$
Where $h^*(n)$ is the true, minimal cost from node $n$ to the goal.

- **Intuition**: An admissible heuristic is **optimistic**. It thinks the goal is closer or cheaper than it actually is. It never exaggerates the cost.
- **Classic Real-World Example**: In road navigation, the **Straight-Line Euclidean Distance** ("as the crow flies") is an admissible heuristic because no real road can be shorter than a straight line.
- **Key Theorem**: **Tree-Search A\* is guaranteed to find the optimal path if $h(n)$ is admissible.**

---

### 💡 Why Does Admissibility Guarantee Optimality? (Proof Sketch)
Suppose a suboptimal goal node $G_2$ is in the queue with true cost $f(G_2) = g(G_2) > C^*$, where $C^*$ is the optimal cost.  
Let $n$ be an unexpanded node on the true optimal path to $G_1$:
$$f(n) = g(n) + h(n) \le g(n) + h^*(n) = C^*$$
Since $f(n) \le C^* < f(G_2)$, the priority queue will **always pop node $n$ before it ever pops $G_2$**! Therefore, A* will expand along the optimal path and discover the true optimal goal $G_1$ before $G_2$ can ever be returned.

---

### 2. Consistency / Monotonicity (The Triangle Inequality)
> *"A heuristic $h(n)$ is **consistent (or monotonic)** if, for every node $n$ and every successor $n'$ generated by an action $a$ with step cost $c(n, a, n')$, the estimated cost from $n$ is no greater than the step cost to $n'$ plus the estimated cost from $n'$."*

$$\mathbf{h(n) \le c(n, a, n') + h(n')}$$

```
                [ n ]
               /     \
    c(n, a, n')       \  h(n)  <-- Direct estimate must be <=
             /         \           step cost + neighbor's estimate!
            v           v
          [ n' ] ╍╍╍╍> [ Goal ]
                 h(n')
```

- **Theorem**: If $h(n)$ is consistent, then:
  1. $f(n)$ values along any path are **monotonically non-decreasing**: $f(n') \ge f(n)$.
  2. **Graph-Search A\* is guaranteed optimal**: The first time A* pops *any* node from the priority queue, the path found to that node is already mathematically guaranteed to be the optimal path! (No need to ever reopen closed nodes!).
  3. Every consistent heuristic is also admissible ($Consistency \implies Admissibility$).

## 3. Complete A* Algorithm Pseudocode

```python
def a_star_search(start, goal):
    # Open List: Priority Queue sorted by f(n) ascending
    open_list = PriorityQueue()
    open_list.insert(start, f = g(start) + h(start))
    
    # Closed List: Set of visited nodes
    closed_list = set()
    
    # Track lowest g-cost discovered so far
    g_score = {start: 0}
    parent = {start: None}
    
    while not open_list.is_empty():
        current = open_list.pop_min()  # Node with lowest f(n)
        
        # Check Goal upon POPPING!
        if current == goal:
            return reconstruct_path(parent, goal)
            
        closed_list.add(current)
        
        for neighbor, step_cost in current.get_neighbors():
            if neighbor in closed_list:
                continue
                
            tentative_g = g_score[current] + step_cost
            
            if neighbor not in open_list or tentative_g < g_score.get(neighbor, infinity):
                parent[neighbor] = current
                g_score[neighbor] = tentative_g
                f_score = tentative_g + h(neighbor)
                
                if neighbor not in open_list:
                    open_list.insert(neighbor, f_score)
                else:
                    open_list.decrease_key(neighbor, f_score)
                    
    return FAILURE
```

Find the optimal path from Start node $S$ to Goal node $C$ using A* Search.

```
                  (1)               (4)
           [ S ] ─────> [ A ] ───────────────> [ C ] (GOAL)
             │                                   ▲
             │ (4)                           (2) │
             v                                   │
           [ B ] ────────────────────────────────┘
```

#### Given Edge Costs $c(u, v)$ and Heuristics $h(n)$:
- **Heuristics**:
  - $h(S) = 6$
  - $h(A) = 4$
  - $h(B) = 3$
  - $h(C) = 0$ (Goal)
- **Step Costs**:
  - $c(S, A) = 1$
  - $c(S, B) = 4$
  - $c(A, C) = 4$
  - $c(B, C) = 2$

---

### Step-by-Step Execution Trace Table

| Step | Action / Node Popped | $g(n)$ | $h(n)$ | $f(n) = g + h$ | Open List `[(Node, g, h, f, Parent)]` | Closed List | Decision & Evaluation |
| :---: | :--- | :---: | :---: | :---: | :--- | :--- | :--- |
| **0** | **Initialize** | $0$ | $6$ | $6$ | `[(S, 0, 6, 6, None)]` | `{}` | Insert start node $S$ with $f(S) = 0 + 6 = 6$. |
| **1** | **Pop $S$** | $0$ | $6$ | $6$ | `[]` | `{S}` | Expand $S$:<br>• Child $A$: $g = 0 + 1 = 1$, $h = 4 \implies f = 1 + 4 = \mathbf{5}$<br>• Child $B$: $g = 0 + 4 = 4$, $h = 3 \implies f = 4 + 3 = \mathbf{7}$ |
| | *After Step 1* | | | | `[(A, 1, 4, 5, S), (B, 4, 3, 7, S)]` | `{S}` | Lowest $f$ is node $A$ ($f=5$). |
| **2** | **Pop $A$** | $1$ | $4$ | $5$ | `[(B, 4, 3, 7, S)]` | `{S, A}` | Expand $A$:<br>• Child $C$: $g = 1 + 4 = 5$, $h = 0 \implies f = 5 + 0 = \mathbf{5}$<br>Insert $(C, 5, 0, 5, A)$ into queue. |
| | *After Step 2* | | | | `[(C, 5, 0, 5, A), (B, 4, 3, 7, S)]` | `{S, A}` | Lowest $f$ is node $C$ ($f=5$). |
| **3** | **Pop $C$** | **$5$** | **$0$** | **$5$** | `[(B, 4, 3, 7, S)]` | `{S, A, C}` | **$C$ IS GOAL NODE! GOAL POPPED $\implies$ STOP!** |

### Notice What Happened!
- At Step 2, node $B$ was sitting in the Open List with $f = 7$.
- If we evaluated path through $B$: $g(C \text{ via } B) = 4 + 2 = 6$, giving $f = 6$.
- Because $5 < 6$, A* never even had to expand node $B$ to reach the goal!
- **Optimal Path Returned**: $\mathbf{S \longrightarrow A \longrightarrow C}$
- **Total Optimal Cost**: $\mathbf{g(C) = 5}$

# PART 2: The AO* Search Algorithm (AND-OR Graphs)

---

## 5. What Is an AND-OR Graph?

In ordinary graphs (OR graphs), branching represents **choices** between independent alternative paths. But in many real-world problem domains, solving a task requires **problem decomposition** (dividing a large problem into multiple compulsory sub-problems).

```
          OR NODE                                     AND NODE
   (Alternative choices)                     (Decomposed Sub-problems)

          [ P ]                                        [ P ]
         /     \                                      /  ⌒  \   <-- Arc denotes AND!
      [ Q ]   [ R ]                                [ Q ]   [ R ]
   Solve Q OR solve R                           MUST solve BOTH Q AND R!
```

### Real-World Examples of AND-OR Decomposition
1. **Assembling an Automobile**:
   - To assemble a car [AND node], you MUST assemble: Chassis **AND** Engine **AND** Transmission **AND** Electrical System.
2. **Medical Treatment**:
   - To cure an infection [OR node], you can use: Oral Antibiotics **OR** [Intravenous Infusion **AND** Hospitalization].
3. **Symbolic Calculus**:
   - $\int (f(x) + g(x)) dx \implies \text{Solve } \int f(x) dx \textbf{ AND } \text{Solve } \int g(x) dx$.

---

## 6. How AO* Works: The Algorithm & Cost Propagation

AO* is an informed search algorithm designed specifically for AND-OR graphs. Unlike A* (which finds a single path), **AO\* finds an optimal SOLUTION TREE**.

### Cost Computation Formulas
For any node $n$:
1. **If $n$ is an OR node** with outgoing edges to children $n_1, n_2, \dots$:
   $$\mathbf{Cost(n) = \min_i \left( c(n, n_i) + Cost(n_i) \right)}$$
2. **If $n$ is an AND node** with outgoing branches to children $n_1, n_2, \dots, n_k$:
   $$\mathbf{Cost(n) = \sum_{i=1}^k \left( c(n, n_i) + Cost(n_i) \right)}$$
   *(If edge costs are 1 per branch, this simplifies to: $Cost(n) = k + \sum_{i=1}^k Cost(n_i)$).*

---

### The 4-Phase AO* Algorithmic Cycle
1. **Top-Down Graph Generation**: Start at the root node. Follow current best branch pointers down to an unexpanded leaf node.
2. **Node Expansion**: Expand the chosen leaf node, generate its successors (either an AND branch or an OR branch), and calculate their initial heuristic values $h$.
3. **Bottom-Up Cost Propagation (Backpropagation)**:
   - This is the defining feature of AO*!
   - Update the cost of the newly expanded node using the formulas above.
   - Propagate the updated cost **backwards up the tree to its parent, grandparent, and all the way to the root**.
   - Re-mark the best branch pointers at each ancestor based on the newly calculated minimum costs.
4. **Termination**: Repeat until the root node is marked as **SOLVED** (all leaves in its marked solution tree are verified terminal goal states).

## 7. Complete Worked Example of AO* (From Course Slides)

### The Problem Graph (Slide 7)

```
                       [ P ]
                      /  |  \
                    /    |    \
            (OR)  /      |      \ (OR)
                /        |        \
              /          |          \
           [ Q ] ⌒ [ R ]           [ S ]
            (AND branch)          /  ⌒  \  (AND branch)
                                [ T ]   [ U ]
```

- To solve $P$, you have two options:
  - **Option 1**: Take the left branch $\implies$ Must solve **$Q$ AND $R$**.
  - **Option 2**: Take the right branch $\implies$ Solve **$S$** alone, where solving $S$ requires solving **$T$ AND $U$**.

---

### Step-by-Step Numerical Cost Trace

#### Initial Heuristic Estimates Given:
- Assume each step/edge cost $c = 1$.
- Given initial heuristics:
  - $h(Q) = 2$
  - $h(R) = 3$
  - $h(S) = 4$
  - $h(T) = 1$
  - $h(U) = 1$

#### Step 1: Evaluate Root $P$
- **Cost of Left Branch (AND node: $Q$ and $R$)**:
  $$Cost(\text{Left}) = [c(P, Q) + h(Q)] + [c(P, R) + h(R)] = (1 + 2) + (1 + 3) = 3 + 4 = \mathbf{7}$$
- **Cost of Right Branch (OR node: $S$)**:
  $$Cost(\text{Right}) = c(P, S) + h(S) = 1 + 4 = \mathbf{5}$$
- **Comparison at Root $P$**:
  $$\min(7, 5) = \mathbf{5} \quad \implies \text{Best choice is to explore Right Branch } (S)!$$

#### Step 2: Expand Node $S$
- We follow the best pointer to $S$ and expand it.
- $S$ decomposes into an **AND branch: $T$ and $U$**:
  $$Cost(S) = [c(S, T) + h(T)] + [c(S, U) + h(U)] = (1 + 1) + (1 + 1) = 2 + 2 = \mathbf{4}$$

#### Step 3: Bottom-Up Cost Propagation to Root $P$
- The cost of $S$ has changed from its initial estimate $h(S) = 4$ to its computed subtree cost $Cost(S) = 4$.
- Propagate back up to Root $P$:
  $$Cost(\text{Right Branch}) = c(P, S) + Cost(S) = 1 + 4 = \mathbf{5}$$
- Re-evaluate Root $P$:
  - Left Branch cost = $7$
  - Right Branch cost = $5$
  - Minimum is still $5$ (Right branch via $S$).
- If $T$ and $U$ are terminal goal states ($h=0$), the entire right subtree is marked **SOLVED**!

### Optimal Solution Tree:
$$\mathbf{\{ P \longrightarrow S \longrightarrow (T \text{ AND } U) \}}$$
$$\mathbf{Total\ Optimal\ Cost = 5}$$

## 8. Head-to-Head Comparison: A* vs. AO*

*(Guaranteed 6–8 mark question)*

| Feature | A\* Search Algorithm | AO\* Search Algorithm |
| :--- | :--- | :--- |
| **Underlying Graph** | Standard state-space graph (**OR Graph** only). | **AND-OR Graph** (Problem-reduction representation). |
| **Goal Output** | A **single optimal path** (sequence of actions). | An **optimal solution tree** (containing all AND branches). |
| **Evaluation Function** | $f(n) = g(n) + h(n)$ | $\min$ over OR children; $\sum$ over AND children. |
| **Cost Revision** | Updates open list frontier dynamically (decrease-key). | **Bottom-up backpropagation** of costs from leaves to root. |
| **Memory Architecture** | Open List + Closed List. | Explicit tree structure with parent and best-branch pointers. |
| **Typical Use Cases** | GPS navigation, 8-puzzle, video game pathfinding. | Theorem proving, task planning, medical diagnosis. |
